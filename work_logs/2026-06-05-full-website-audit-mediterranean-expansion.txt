D.5 KNOWLEDGE BASE ARCHITECTURE RECOMMENDATION
----------------------------------------------------------------------

CURRENT STATE:
  - No knowledge base exists
  - Backend (chat.php) is not connected
  - Widget is client-side only

RECOMMENDED ARCHITECTURE:

1. Knowledge Base Structure:
   /ai/knowledge/
     malta.json          — Malta-specific: areas, transfers, tips, pricing
     sicily.json         — Sicily content
     mallorca.json       — Mallorca content
     general.json        — Booking process, company info, policies
     faq.json            — Common questions across all destinations

2. Backend Options (in order of recommendation):
   a) Claude API (Anthropic) — Best for nuanced travel advice
      - System prompt with destination knowledge
      - User message forwarded with context
      - Session-based conversation memory
      - Cost: ~$0.003-0.01 per conversation turn

   b) OpenAI API — Alternative
      - Similar architecture
      - GPT-4o-mini for cost efficiency

   c) Rule-based fallback — For cost control
      - Pattern matching for common questions
      - JSON knowledge base lookup
      - Falls back to WhatsApp for complex queries

3. Session Architecture:
   - Generate UUID per visitor (stored in sessionStorage)
   - Send session ID with each message
   - Backend maintains conversation context per session
   - Optional: persist to database for analytics

4. Multi-Destination AI:
   - Detect destination from URL path or user question
   - Load destination-specific knowledge
   - System prompt adapts per destination
   - Quick chips change per destination page
